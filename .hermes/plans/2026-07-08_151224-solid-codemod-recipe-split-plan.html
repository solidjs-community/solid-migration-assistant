Summary

The Solid package already looks like a real Codemod package, but it mixes many domains: imports, JSX types, JSX shape rewrites, runtime safe rewrites, review comments, JSON config, and dogfood skill installation. The registry pattern is to keep these as smaller packages and expose one recipe that runs them in order.

Current
One broad solid-codemod package plus dogfood repos/reports.
Target
Six focused solid-v2-* codemods plus one recipe.
Migration style
Copy-first, delete unrelated behavior, verify, then extract shared helpers.

solid-v2-imports

Module moves and safe import renames: solid-js/web→@solidjs/web, safe API renames, aliases/collisions.

solid-v2-jsx-types

Type-only moves: JSXElement→Element, renderer-owned types to @solidjs/web.

solid-v2-jsx-shapes

Context providers, dynamic components, error fallback, Reveal props, intrinsic attrs, classlist, simple prop destructuring.

solid-v2-runtime-safe

Call/runtime rewrites: createMemo, createComputed, createSelector, splitProps, stores, cleanup, resources, testing-library flush.

solid-v2-review-markers

Idempotent comments for semantic migrations needing human intent.

solid-v2-json-config

Package dependency ranges, JSX config, tsconfig/jsconfig/package-lock updates.

Execution Sequence

1. Snapshot baseline
pnpm test and pnpm check-types in current package.
2. Add root scripts
Root package.json: test, check-types, ci.
3. Split JSON first
Create solid-v2-json-config from existing isolated json-config.ts.
4. Split source transforms
Create imports → JSX types → JSX shapes → runtime-safe → review-markers, moving fixtures with each package.
5. Extract shared helpers
Only after package tests pass, add packages/solid-codemod-shared.
6. Add recipe
Create solid-v2-migration-recipe that delegates to the six focused codemods.
7. Compatibility
Convert or deprecate old solid-codemod.
8. Dogfood dry runs
Run recipe against .repos/solid-primitives, .repos/kobalte, .repos/solid-router.

Each split package should own its copied fixtures and run pnpm test + pnpm check-types independently.

Risks

  • Ordering drift: recipe order must be explicit; add integration fixtures for cross-package interactions.
  • Helper divergence: copy-first is safer, but extract shared helpers once behavior is protected.
  • Marker duplication: review-marker package must be idempotent.
  • Over-splitting: keep six packages, not one per tiny AST rule.

Definition of Done

  • Root workspace scripts exist.
  • Each new package has package metadata, workflow, README, tests, and typecheck.
  • Existing fixtures are redistributed by ownership.
  • Recipe composes smaller codemods in documented order.
  • Old solid-codemod remains compatible or clearly deprecated.
  • Root pnpm run ci passes.
  • Dogfood dry runs complete or blockers are documented.
