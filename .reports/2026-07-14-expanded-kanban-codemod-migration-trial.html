What migrated correctly

Configuration and renderer ownership

  • Package pins and jsxImportSource moved to the intended beta.17 tuple.
  • render, Portal, and ComponentProps moved to @solidjs/web where exercised.
  • Fresh npm resolution produced a coherent lockfile for the pinned versions.

Narrow proven source shapes

  • The exact onMount + one nested onCleanup shapes became onSettled with returned cleanup.
  • The specifically named setBoard path write and immediate persistence shape gained storePath / flush.
  • The specifically named setBoard(produce(...)) shape lost the obsolete wrapper.
  • Unsupported one-argument effects received idempotent S2-EFFECT-001 markers.
These are useful transformations, but they do not form a closed migration. A codemod should not claim successful delivery until syntax, package exports, type checking, and explicit manual-review obligations are reconciled.

Critical findings

P0 · deterministic corruption

Index conversion rewrites closing tags without rewriting matching openings

The expanded fixture uses valid Solid 1 <Index each={...} fallback={...}> elements. The opening-tag regex only accepts an each prop followed immediately by >, while the closing-tag replacement rewrites every </Index>. Both openings remain Index; both closings become For.

Evidence: migrated src/components/BoardView.tsx:106–111 and :115–132; transform scripts/source.ts:301–307. TypeScript and the Solid Vite plugin both report the mismatch. The workflow still exits 0.
<Index each={props.selectedCards} fallback={<p>No selected cards</p>}>
  ...
</For>
P0 · package closure

Removed solid-js/store imports are deliberately retained when their helpers remain in use

unwrap is still referenced in App.tsx and board history, so the import rewrite keeps it in solid-js/store. Solid beta.17 exports no ./store subpath. Vite therefore fails its module graph before application code can run.

Evidence: migrated src/App.tsx:2 and src/board/state.ts:2; transform retention logic scripts/source.ts:76–84; installed package exports only ., ./types/*, and ./package.json. Vite reports “Missing ./store specifier in solid-js package.”
P0 · API closure

The workflow leaves a broad Solid 1 API inventory unchanged

The import merger keeps unknown solid-js specifiers instead of classifying them against the target export surface. The fixture therefore retains APIs that beta.17 does not export:

  • createSelector in App.tsx
  • Index and splitProps in BoardView.tsx
  • createResource, ErrorBoundary, Suspense, and useTransition in details.tsx
  • mergeProps, splitProps, and JSXElement in preferences.tsx
  • batch in state.ts, plus renderer-owned JSX types in App.tsx and editor.tsx
Evidence: direct beta.17 export probe reports these names absent; virtual parser-unblock compilation reports 52 application diagnostics. The Solid 2 migration guide maps these APIs to different primitives or deliberate manual redesigns.
P0 · runtime trap

S2-EFFECT-001 is a comment, not a delivery gate

The workflow correctly recognizes two one-argument effects as unsupported, but it only adds comments and completes successfully. In beta.17 the compatibility signature returns never, so a statement-position call does not necessarily produce a TypeScript error. It fails when executed.

Evidence: markers precede the persistence effects in src/board/state.ts and src/preferences.tsx. A direct beta.17 browser-condition probe throws [MISSING_EFFECT_FN] createEffect requires both a compute function and an effect function.
P0 · store migration

Name-specific store rewriting misses most of the fixture’s real store writes

The transform is hard-coded around setBoard. The expanded fixture intentionally aliases that setter to updateBoard and adds independent history and preferences stores. Their Solid 1 path overloads and replacement calls survive unchanged.

Evidence: state.ts retains path setters at lines 25–30, 58, 80, 89–103 and replacement at 110; preferences.tsx retains path setters at 61, 66, and 71. The isolated board probe reports 22 errors, including wrong arities and invalid replacement shapes. Transform guards explicitly test setBoard at scripts/source.ts:160–184 and :248–269.
P1 · JSX composition

Textual classList replacement creates duplicate class attributes

A card already has a static class="card migration-card". Replacing only the token classList={{ with class={{ produces a second class attribute rather than merging the static and conditional values.

Evidence: migrated BoardView.tsx:33–34; unconditional replacement at scripts/source.ts:310. Once the tag mismatch is virtually removed, TypeScript reports TS17001: JSX elements cannot have multiple attributes with the same name.
P1 · component model

Context providers and helper renames are not migrated

The preferences feature uses mergeProps, splitProps, and <PreferencesContext.Provider>. Solid 2 expects merge, omit, and context-as-provider. The codemod does not inspect or mark these shapes.

Evidence: preferences.tsx:47–48 and :76; isolated probe reports eight errors, including absent exports, three store setter overload failures, missing JSXElement, and no Provider property.
P1 · renderer/type surface

Renderer-owned JSX types and directive attributes remain incompatible

Moving ComponentProps and Portal is not enough. JSXElement and JSX.EventHandlerUnion remain imported from or addressed through solid-js, while custom use:clickOutside and use:autofocus attributes no longer satisfy the target JSX types.

Evidence: isolated editor.tsx probe reports five errors at lines 1, 44, 53, and 57; the application-wide virtual-unblock probe also reports App.tsx:59.
P1 · delivery contract

The workflow has no postcondition that connects “transformed” to “migrated”

Both automatic nodes complete and the CLI exits 0 even though the generated source is unparsable and contains known manual-review markers. The current workflow does not run dependency installation, target-export validation, parse/type checks, or a finding gate.

Evidence: workflow workflow.yaml:5–38 contains only config and source transforms. The README asks the operator to validate afterward, but the machine success status arrives before any of those checks.
Positive · repeatability

The second pass is byte-idempotent

The dirty trial required --allow-dirty. The second run again exited 0. SHA-256 hashes of every tracked trial file before and after were identical.

Interpretation: repeatability is real and worth preserving. It is not semantic correctness: the current invalid result is a stable fixed point.

Recommended remediation order

  1. Prevent source corruption first. Replace regex-paired JSX rewrites with AST element transforms that update opening and closing nodes together and preserve arbitrary props. Add the two fallback cases as regression fixtures.
  2. Add a migration postcondition. Parse every touched source file, validate every target import against installed/export-manifest knowledge, fail on unresolved blocking findings, and surface a nonzero workflow result before users trust the diff.
  3. Build an API inventory/classifier before rewriting. Every Solid import should land in one of: safely transformed, still valid in beta.17, explicitly manual with a blocking finding, or unsupported. Never silently retain an absent export.
  4. Resolve store setters by binding, not spelling. Discover setters from createStore destructuring and follow aliases. Convert path writes with storePath, draft callbacks, or a reviewed semantic strategy; treat batch and same-tick persistence separately.
  5. Make effect review actionable. Either split proven compute/apply effects or emit a structured blocking finding. A source comment can supplement the finding, not replace it.
  6. Use syntax-aware class composition. Merge static strings and dynamic class objects into one valid Solid 2 class expression; preserve order and truthiness.
  7. Add dedicated component/type migrations. Cover context-as-provider, merge/omit, renderer-owned JSX types, and an explicit policy for custom directives.
  8. Route async/control-flow redesign to a separate phase. createResource/useTransition are semantic migrations to async computations, Loading, Errored, pending/optimistic APIs—not safe name substitutions. Emit a structured AI/manual task with the relevant local Solid 2 documentation.
  9. Keep the current hash-idempotency check. Expand it with syntax, export closure, typecheck, build, and focused behavioral gates so the fixed point is valid as well as stable.
