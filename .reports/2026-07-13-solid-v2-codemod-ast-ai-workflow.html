Build a Codemod workflow where AST narrows the problem and AI resolves only bounded semantic residue.

This report replaces the workflow portion of the earlier plan with an executable Codemod design: v1 workflow nodes, JSSG and ast-grep steps, manual triggers, state, AI handoffs, deterministic receipts, validation, and Campaign sharding.

Solid target: 2.0.0-beta.17 Solid commit: a51cac19 Codemod source reviewed: eaeb7a9 Default path: deterministic AST AI path: explicit + reviewable

The corrected product model

The previous report described a migration decision pipeline, but not the concrete Codemod execution model. The product should be a Codemod package with named workflows. Its core loop is:

inventory → deterministic transforms → residual classification → approval → bounded AI edits → deterministic verification → report.

AST is not merely one implementation detail. It is the control plane for AI: it proves safe rewrites, emits stable markers for uncertain sites, builds candidate manifests, and later verifies that AI touched only the intended semantic clusters.

Recommended first milestone: one runnable guided workflow that migrates imports deterministically, detects one ambiguous reactive-ownership case, hands only that case to AI, rejects out-of-scope edits, and produces a truthful completion report.

Design against Codemod as it exists

Nodes are transaction boundaries

Nodes form a dependency DAG. Steps within a node run sequentially. A failed task discards its diff, so each mutating node should end with the verification that proves those edits.

AI is a step, not a node type

A node is automatic or manual. An ai action is one step inside it. The workflow must create approval by putting AI behind a node-level manual trigger.

No generic step outputs

steps.*.outputs is not wired. Handoffs must use changed files, target-local artifacts, or workflow state—not imagined output variables.

Ship three named workflows, not one overloaded graph

Default

safe

Inventory, deterministic JSSG/ast-grep transforms, markers, validation, and report. No AI node and no pointless approval gate.

Use: CI, conservative adopters, initial repository assessment.

Local guided

guided-ai

The safe path plus a manual approval node and sequential AI domain nodes. Each AI node is paired with deterministic scope and behavior checks.

Use: one application checkout with a human reviewing the plan and final diff.

Cloud only

campaign-ai

Dependency-aware shard discovery, matrix tasks, task branches, draft PRs, and per-shard AI. It begins after the safe mechanical baseline is merged.

Use: large monorepos and organization-scale rollout.

Codemod supports multiple named workflows in one package. The CLI selects them with --workflow-name; keep safe as the default.

Why three AI nodes? A failed task discards that node’s diff. Splitting reactivity, async, and DOM/JSX means a bad async attempt does not erase a previously verified reactivity migration. It also gives each prompt a smaller vocabulary, candidate set, and test surface.

The AST → AI handoff is a checked protocol

Codemod does not attach previous step output or a file set to an AI step. Therefore the deterministic phase must make the handoff visible in the working tree.

Stable source marker

// codemod:solid2-review
// id: S2-ASYNC-RESOURCE-001:7f2a
// cluster: user-resource
// manifest: .solid2-codemod/candidates/async.json

The marker is searchable, deduplicated by decision code + AST anchor, and remains until a verified decision resolves it.

Target-local candidate manifest

{
  "domain": "async",
  "target": "solid-2.0.0-beta.17",
  "allowedFiles": ["src/user.tsx", "src/UserView.tsx"],
  "candidates": [{
    "id": "S2-ASYNC-RESOURCE-001:7f2a",
    "evidence": ["resource.loading", "resource.error", "refetch"],
    "checks": ["pnpm typecheck", "pnpm test UserView"]
  }]
}

JSSG can write this inside the target without unrestricted filesystem capability; the default filesystem is sandboxed to the target directory.

AI completion receipt

Every AI prompt must write .solid2-codemod/ai/<domain>.json with candidate IDs attempted, files changed, markers retained/removed, commands run, and their exit codes. A deterministic step immediately validates the receipt against the actual diff and manifest.

This is not paperwork. In the current runtime, parent-agent handoff or a missing API key can print [AI INSTRUCTIONS], skip built-in execution, and still return success. If the receipt is absent, the node fails. “Completed” can no longer silently mean “AI never ran.”

Prompt contract

  1. Read the compatibility manifest and exactly one domain candidate manifest.
  2. Modify only allowedFiles; AI has no native include/exclude field.
  3. Resolve only listed marker IDs. Do not opportunistically modernize nearby code.
  4. Preserve public API, reactive ownership, evaluation timing, and error/loading behavior unless the candidate explicitly authorizes a change.
  5. Remove a marker only after its listed checks pass. Otherwise retain it and record the blocking evidence.
  6. Write the completion receipt. The prose final response is only a log and is not machine-consumable.

Keep Codemod’s default system prompt so target-root context is preserved. Set max_steps and a minimal tool list explicitly. Do not rely on AI-local timeout, working directory, environment, or dry-run fields until runtime tests prove them.

Representative guided workflow YAML

This is a design skeleton, not a claim that the scripts already exist. It deliberately uses current, documented v1 constructs and avoids templates, nested workflows, generic step outputs, container runtimes, and nested matrices.

version: "1"

params:
  schema:
    verify_command:
      name: Verification command
      type: string
      default: "pnpm typecheck && pnpm test"

nodes:
  - id: preflight
    name: Capture baseline and target profile
    steps:
      - name: Capture baseline
        run: node ./scripts/solid2-preflight.mjs

  - id: inventory
    name: Inventory Solid usage with AST
    depends_on: [preflight]
    steps:
      - name: Build inventory
        js-ast-grep:
          js_file: scripts/inventory.ts
          language: tsx
          semantic_analysis: workspace
          include: ["**/*.ts", "**/*.tsx", "**/*.js", "**/*.jsx"]
          exclude: ["**/node_modules/**", "**/dist/**"]

  - id: mechanical
    name: Apply and prove deterministic migration
    depends_on: [inventory]
    steps:
      - name: Update package and config
        run: node ./scripts/solid2-config.mjs
      - name: Rewrite imports and types
        js-ast-grep:
          js_file: scripts/imports-and-types.ts
          language: tsx
          semantic_analysis: workspace
      - name: Rewrite exact JSX shapes
        js-ast-grep:
          js_file: scripts/jsx-shapes.ts
          language: tsx
          semantic_analysis: file
      - name: Rewrite proven local runtime patterns
        js-ast-grep:
          js_file: scripts/local-runtime.ts
          language: tsx
          semantic_analysis: file
      - name: Classify semantic residue and insert markers
        js-ast-grep:
          js_file: scripts/classify-residuals.ts
          language: tsx
          semantic_analysis: workspace
      - name: Apply trivial cleanup
        ast-grep:
          config_file: rules/cleanup.yml
      - name: Reject mechanical regressions
        run: node ./scripts/solid2-verify.mjs mechanical

  - id: approve-ai
    name: Approve bounded semantic migration
    depends_on: [mechanical]
    trigger:
      type: manual
    steps:
      - name: Print AI plan
        run: node ./scripts/solid2-print-plan.mjs

  - id: ai-reactivity
    name: Resolve reactivity and ownership candidates
    depends_on: [approve-ai]
    steps:
      - name: Resolve marked reactivity candidates
        ai:
          max_steps: 40
          tools: [glob, str_replace_based_edit_tool, task_done]
          prompt: |
            Read .solid2-codemod/candidates/reactivity.json.
            Modify only allowedFiles and only listed marker IDs.
            Preserve ownership and evaluation timing.
            Write .solid2-codemod/ai/reactivity.json.
      - name: Prove scope, receipt, and behavior
        run: node ./scripts/solid2-verify.mjs ai-reactivity

  - id: ai-async
    name: Resolve async and resource candidates
    depends_on: [ai-reactivity]
    steps:
      - name: Resolve marked async candidates
        ai:
          max_steps: 40
          tools: [glob, str_replace_based_edit_tool, task_done]
          prompt: |
            Read .solid2-codemod/candidates/async.json.
            Modify only allowedFiles and only listed marker IDs.
            Preserve readiness, error, revalidation, and mutation UX.
            Write .solid2-codemod/ai/async.json.
      - name: Prove scope, receipt, and behavior
        run: node ./scripts/solid2-verify.mjs ai-async

  - id: ai-dom
    name: Resolve DOM, JSX, and directive candidates
    depends_on: [ai-async]
    steps:
      - name: Resolve marked DOM and JSX candidates
        ai:
          max_steps: 40
          tools: [glob, str_replace_based_edit_tool, task_done]
          prompt: |
            Read .solid2-codemod/candidates/dom-jsx.json.
            Modify only allowedFiles and only listed marker IDs.
            Do not guess renderer ownership or public API intent.
            Write .solid2-codemod/ai/dom-jsx.json.
      - name: Prove scope, receipt, and behavior
        run: node ./scripts/solid2-verify.mjs ai-dom

  - id: finalize
    name: Verify and report the migration
    depends_on: [ai-dom]
    steps:
      - name: Re-inventory final state
        js-ast-grep:
          js_file: scripts/final-inventory.ts
          language: tsx
          semantic_analysis: workspace
      - name: Run full validation and write report
        run: node ./scripts/solid2-verify.mjs final
The exact relative-path behavior of shell scripts must be confirmed in the first workflow spike. If run executes from the target rather than the package root, publish a stable package script entry point rather than copying helpers into the target. This is a runtime test, not a schema question.

Campaign sharding is a second-stage product

Do not shard by arbitrary file count for Solid semantic work. Resource ownership, effects, exports, and JSX consumers cross file boundaries. Use a custom shard function to parse imports and group connected candidate files. The official shard API can use ast-grep and returns _meta_files, which becomes the authoritative file scope for downstream JSSG.

Phase A: merge the safe baseline

Run config/import/type/locally-safe transforms as one reviewed baseline PR. This gives every semantic shard the same dependency and type environment.

Phase B: fan out residual clusters

A shard step dry-runs the residual detector, writes shard objects to state, and a manual matrix node opens one draft PR per dependency-connected cluster.

state:
  schema:
    semantic_shards:
      type: array
      items:
        type: object

nodes:
  - id: evaluate-shards
    name: Build semantic shards
    steps:
      - name: Group connected candidate files
        shard:
          method:
            function: scripts/shard-by-dependency.ts
          target: "."
          output_state: semantic_shards
          js-ast-grep:
            js_file: scripts/classify-residuals.ts
            language: tsx
            semantic_analysis: workspace

  - id: migrate-shard
    name: Migrate semantic shard
    depends_on: [evaluate-shards]
    trigger:
      type: manual
    strategy:
      type: matrix
      from_state: semantic_shards
    branch_name: "solid2-${{ matrix.name }}-${{ task.signature }}"
    pull_request:
      title: "refactor: migrate Solid 2 ${{ matrix.name }}"
      draft: true
    steps:
      - name: Apply shard-safe AST work
        js-ast-grep:
          js_file: scripts/shard-transform.ts
          language: tsx
          semantic_analysis: workspace
      - name: Resolve shard residue
        ai:
          max_steps: 40
          prompt: |
            Work only on files listed for shard ${{ matrix.name }}.
            Resolve only its candidate manifest and write a receipt.
      - name: Reject out-of-shard edits and run tests
        run: node ./scripts/solid2-verify.mjs shard
Important: _meta_files automatically scopes downstream JSSG, but it does not natively scope AI. The prompt and post-AI diff guard must enforce the same list. Cloud task branches provide isolation; local parallel matrix AI does not.

Required invariants

  • Safe mode never invokes or waits for AI.
  • A second complete run produces no additional source changes or duplicate markers.
  • Every removed marker is represented in a valid receipt and its acceptance checks passed.
  • Every AI-changed file belonged to that domain or shard allowlist.
  • Baseline failures are distinguished from newly introduced failures.
  • A skipped AI runtime cannot yield a green guided workflow.
  • Reports, metrics, candidate counts, and source markers agree.

Implementation roadmap: tracer bullets through the real workflow

Prove Codemod runtime assumptions

Create a throwaway v1 workflow that verifies shell working directory, target-local file handoff, JSSG state APIs, $STATE_OUTPUTS, manual resume, failure diff discard, AI no-key/handoff behavior, and the current CLI version. Record results before designing helpers.

Build one safe vertical slice

One web app: baseline capture → AST inventory → proven solid-js/web package/import move → mechanical verification → final report → second-run no-op.

Add one AST → AI case

Choose one ownership-sensitive lifecycle/effect case. JSSG emits a stable marker and manifest; a manual AI node edits only its closure; receipt and scope guard prove the result.

Separate the three semantic domains

Grow reactivity, async, and DOM/JSX candidate schemas and prompts independently. Each gets domain tests and a focused verification command.

Expand deterministic coverage

Port proven config/import/type/JSX/runtime rules into focused scripts. Every rule declares its evidence, fallback marker, compatibility revision, and idempotency fixtures.

Ship safe and guided workflows

Validate schema, run end-to-end fixtures, document AI execution modes, and make safe the default. Do not publish until skipped AI is detectable.

Only then add Campaign sharding

Build dependency-connected shards from residual markers, prove cloud task isolation and draft PR behavior, and enforce the AI allowlist with post-edit diff guards.
