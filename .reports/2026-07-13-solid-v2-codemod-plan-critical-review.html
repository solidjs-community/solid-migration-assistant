Three-perspective review · 13 July 2026

Keep the AST-controlled AI idea. Replace the workflow contract around it.

Three parallel reviewers examined the earlier AST → AI plan as a Codemod runtime engineer, a Solid migration expert, and a migration product/QA lead. Their independent conclusion is consistent: the plan has a strong control-plane idea, but the guided workflow is not safe or executable enough to build as written.

Reviewed plan: AST → AI workflow Codemod CLI checked: 1.12.7 Solid target: 2.0.0-beta.17 Reviewers: runtime · semantics · delivery Result: redesign before implementation

Executive verdict

The durable insight is correct: deterministic AST analysis should inventory, narrow, and verify any AI work.

The proposed execution model is not: local failure is not transactional, the human approves before seeing the plan, the compatibility profile omits the compiler, fixed “reactivity / async / DOM” AI domains cut through real behavioral units, and the mechanical node can fail on the very semantic residue it intends to hand to AI.

Recommendation: do not start with three real AI nodes. First ship a clean, deterministic, behavior-proven vertical slice on a committed Solid 1 baseline. Then add classifier-only residue, a fake AI harness, and one isolated real-AI cluster canary.

Current evidence changes the priority

Transforms

All six current transform scripts are still explicit no-ops. The project has orchestration scaffolding but no working deterministic migration rule.

Migrated API fixture

The committed Solid 2 snapshot in .repos/test currently exits typecheck with 59 TypeScript errors, including duplicate imports and removed APIs.

Behavior fixture

The new Kanban fixture has eight passing Solid 1 browser tests, but it is uncommitted and has no Solid 2 result yet. It is a promising oracle, not a completed before/after proof.

The next unit of progress should be measured as “one real application migrated and behaviorally verified,” not “more workflow machinery authored.”

Consensus: six release-blocking corrections

P0

1. Local nodes are not transaction boundaries

The earlier report says a failed task discards its diff and uses that assumption to justify separate AI nodes. In local runs, JSSG and AI write directly to the checkout; failure changes task status but does not restore files. Disposable Campaign worktrees provide isolation, local guided mode does not.

Correction: either state that local guided mode is non-transactional, or run each semantic cluster in an isolated worktree and apply a validated patch only after deterministic checks. Snapshot/restore is the minimum fallback, but worktree isolation is the clearer contract.

P0

2. The human approval gate is blind

The step that prints the AI plan is inside the manual-triggered node. Manual nodes pause before their steps execute, so the reviewer must resume before seeing what they supposedly approved.

Correction: generate and display plan.json in an automatic node. Bind approval to the base commit plus plan, compatibility, and candidate hashes. The first post-resume step must reject drift before any provider call.

P0

3. The compatibility tuple omits the JSX compiler

Solid source semantics are partly defined by compiled output. The Solid 1 Kanban uses vite-plugin-solid@2.11.12 and a preset that emits solid-js/web and recognizes old control-flow built-ins. Beta.17 uses a 3.x-next plugin/preset that emits @solidjs/web and recognizes Loading, Reveal, and Errored.

Correction: profile and migrate runtime, renderer, Babel preset, Vite/Rollup integration, refresh integration, JSX type owner, and directly used DOM-expression packages atomically. Add a compiled-output assertion, not only a source import assertion.

P0

4. Fixed AI domains split real Solid behavior clusters

A resource producer, consuming effect, store writes, Loading/Errored boundaries, refresh/mutation controls, and pending UI form one behavioral unit. “Reactivity → async → DOM” can verify one half and invalidate it in the next node.

Correction: make the AI unit a dependency-connected semantic cluster. Domain is metadata, not the transaction boundary. Build edges from symbol flow, props/context, boundary ancestry, resource/action handles, exports, and related tests, then topologically process clusters.

P0

5. “No new errors” deadlocks before AI

Once Solid 2 dependencies are installed, expected semantic residue—removed createResource, on, createComputed, or one-argument createEffect—becomes new build/type errors. Rejecting every new error prevents the workflow from reaching the semantic stage.

Correction: reject only unmapped regressions. Every expected diagnostic must map to one candidate ID and signature. Safe mode may finish as partial with a reconciled blocking ledger; only final verification requires a clean target.

P0

6. AI receipts are self-attestation, not proof

The YAML asks AI to run checks and write exit codes but does not grant bash; it also restricts edits to source allowlists while requiring a new control file. Even with tools enabled, an AI-authored exit code cannot prove a command ran.

Correction: AI may write claims—candidate outcomes, changed-file claims, unresolved reasons. A deterministic post-step process measures the actual diff, runs checks, captures exit codes and hashes, and creates the authoritative receipt. Separate source and control-artifact allowlists.

Runtime review: make state, scope, and paths measurable

P1

Per-step scope attribution is undefined

During the async cluster, a repository-wide git diff also contains mechanical and earlier semantic changes. The validator cannot attribute the current step from that diff alone.

Correction: snapshot file existence, content hashes, mode, and repository file list immediately before each AI invocation. Compare after it, including created/deleted/renamed/symlink/binary cases.

P1

Shell helper paths are not proven package-relative

JSSG script paths resolve from the bundle; run: node ./scripts/... may resolve from the target. The report acknowledges this but still presents the uncertain form as representative YAML.

Correction: prove target path, shell pwd, CODEMOD_PATH, and cross-platform invocation first. Prefer a published executable/package entry point over shell-specific path interpolation.

P1

Candidate aggregation can race

JSSG processes files concurrently. Per-file transforms rewriting one manifest can lose candidates or produce nondeterministic output.

Correction: emit unique per-file fragments and consolidate in a deterministic later step, or use proven workflow locks. Test 100-file multi-threaded classification for completeness, ordering, duplicates, and second-run identity.

P1

Campaign dependency is scheduling, not branch lineage

A downstream Campaign node does not automatically inherit an upstream node’s branch. Residual shards must start from an already merged safe baseline, and the expected base SHA must be enforced.

P2

Current platform assumptions need a living compatibility test

The current CLI is 1.12.7. Current docs describe step conditions, commit checkpoints, multiple workflows, task-context values, and improved handoffs. Keep a runtime conformance fixture rather than freezing implementation claims from one source commit into the product plan.

Delivery review: define trust, recovery, and “done”

Execution status is not migration status

Codemod Completed means a task succeeded and its diff applied. It does not mean all candidates resolved or the app is migration-ready.

Use executionStatus separately from migrationStatus: ready | partial | blocked.

Every candidate needs one disposition

Use explicit terminal outcomes such as ast_resolved, ai_resolved, human_required, unsupported, verification_failed, scope_violation, and stale.

Recovery is part of the product

Record base SHA, run ID, workflow and compatibility hashes, original dirty patch, candidate/plan hashes, provider/model, and prompt version. Reject stale receipts and define exact rollback.

Budgets and privacy are gates

Pin model/provider, cap candidates/files/shards/calls/cost, skip empty clusters, exclude secrets/vendor/generated files, resist source prompt injection, and redact logs/artifacts.

Reconciliation invariant:
totalCandidates = astResolved + aiResolved + humanRequired + unsupported + blocked + verificationFailed + retained
A retained or failed candidate can never yield migrationStatus: ready.

What the earlier plan got right

AST as AI control plane

Keep deterministic discovery, bounded candidate creation, source provenance, scope checks, and post-edit verification.

Separate products

Keep safe, guided-ai, and campaign-ai distinct. Safe can reach GA without waiting for AI maturity.

AI remains optional

Keep explicit approval, narrow prompts, retained markers, deterministic checks, and human-required routing for public behavior choices.

Seven spikes that should precede product implementation

  1. Local vs Campaign rollback: edit, then fail; measure surviving changes, worktree behavior, shell pwd, target path, and bundle path.
  2. Approval drift: generate a plan, pause, mutate source, resume; fail before AI because the approval envelope changed.
  3. AI execution modes: normal Rig, no key, parent handoff, and external-agent mode; skipped execution must never pass without measured output.
  4. Scope attribution: allowed edit, receipt creation, forbidden edit, rename, deletion, symlink, and binary; measure and restore only current-cluster changes.
  5. Concurrent aggregation: classify 100 files with multiple threads; output must be complete, ordered, duplicate-free, and second-run identical.
  6. Toolchain tracer bullet: committed Kanban Solid 1 baseline → atomic compiler/runtime/import/lockfile migration → same eight tests on Solid 2 → second-run no-op → rollback.
  7. Diagnostic ledger: seed one expected semantic error and one unrelated regression; permit only the candidate-mapped error and fail the unexplained one.

Revised rollout sequence

Define status and artifact schemas

Version run, profile, candidate, plan, approval, claims, receipt, and final report. Lock reconciliation and exit-code semantics first.

Prove runtime and recovery

Resolve local transactionality, path resolution, manual pause/resume, drift rejection, interruption, stale artifacts, and rollback.

Commit the Kanban baseline

Create an immutable Solid 1 commit/tag and reproducible clean-clone test harness. The current untracked nested repo is not yet a migration baseline.

Ship one safe vertical slice

Profile npm/Vite, migrate the full compiler/runtime/renderer tuple and solid-js/web import, install lockfile graph, run unchanged tests, prove no-op rerun and rollback.

Add classifier-only residue

One ownership-sensitive candidate generates stable fragments and a visible plan. No real AI. Prove accounting, idempotence, and expected-error mapping.

Use a deterministic fake AI harness

Exercise no-run, malformed/stale claims, scope escape, retained marker, failed check, prompt injection, empty cluster, interruption, and budget exhaustion.

Run one real-AI canary

One connected cluster in an isolated worktree, pinned model/prompt, explicit hashed approval, hard budget, measured receipt, deterministic oracle, human review.

Expand deterministic rules and fixtures

Each rule needs golden, collision, shadowing, no-op, second-run, composed, and behavior tests. Reclassify proof-required transforms conservatively.

Release safe GA, guided beta

Safe should not wait for AI. Guided graduates only after published scope-escape, success, review, variance, cost, and latency thresholds.

Add Campaign last

Require merged safe-baseline SHA, bounded semantic closures, shard deduplication, aggregate reconciliation, canary waves, stop-the-line thresholds, and rollback through draft PR closure.
