Glossary Decisions

The existing terms Safe Mechanical Migration, Semantic Migration Site, and Review Marker were preserved. The discussion added or refined these terms in CONTEXT.md:

  • Best-Effort AI Migration: Explicitly requested mode where AI may rewrite semantic sites after the safe mechanical pass.
  • Target Profile: Package-level classification for web, hyperscript, custom renderer, or renderer-neutral migration behavior.
  • Migration Report: Generated record of decisions, evidence, confidence, edits, skipped sites, and verification.
  • Role-Aware Dependency Migration: Dependency updates based on application/library/renderer role.
  • Compatibility Manifest: Version policy source for Solid 2 package/tooling ranges.
  • Renderer-Owned JSX Type and Renderer-Neutral Renderable: Distinguish renderer JSX types from Solid core renderable values.
  • Flush Boundary: A deliberate synchronous visibility point for queued Solid 2 updates.
  • Effect Split: Solid 2 compute/apply effect shape.
  • Initial Prev Migration: Migration from old initial value arguments to default prev parameters.
  • Lifecycle-Aware Migration: Migration respecting onSettled/createTrackedEffect cleanup and nested primitive restrictions.
  • Diagnostic-Driven Migration: Migration loop using Solid 2 dev diagnostics.
  • Resource Cluster: Connected creation/consumption/loading/error/refetch/mutation sites around a resource.
  • Review-Only Migration Site: Site surfaced but not automatically rewritten, even in best-effort mode.
  • Directive Migration: Migration from use: directives to ref directive factories.
  • Verification Loop: Phased edit/test/diagnostic loop.
  • Public API Preserving Migration: Library migration preserving exported contracts unless breaking mode is explicit.

Workflow Architecture

ResolvedDeterministic default, explicit AI mode.

The normal solid-codemod workflow should auto-apply only safe mechanical changes. AI auto-apply is allowed only under explicit Best-Effort AI Migration.

ResolvedSplit workflows.

Keep the deterministic Codemod CLI package testable and publishable. Put package profiling, AI planning, diagnostic loops, and report generation into the installed package skill / best-effort orchestrator.

ResolvedPreflight scanner first.

Before editing, scan for target profiles, package roles, public exports, test/build commands, Solid API inventory, and risky clusters.

ResolvedTarget-profile aware migration.

Do not assume every package is a web app. Classify packages as web app, web component library, renderer-neutral library, hyperscript, or custom renderer. In best-effort mode, AI may infer ambiguous profiles but must record evidence and confidence.

ResolvedRole-aware dependencies.

Applications get runtime dependencies. Published libraries keep solid-js and required renderer packages in peerDependencies, with matching dev dependencies only when needed. Avoid same-group mirroring.

ResolvedCompatibility manifest.

Version ranges should come from a manifest shipped with the codemod. Deterministic runs use pinned manifest policy; best-effort mode may check for newer compatible versions and report choices.

ResolvedPer-package monorepo workflow.

Monorepos migrate per package using the workspace graph, local target profile, dependency role, and local test commands. Results aggregate into a workspace report.

ResolvedPhased verification loop.

Run deterministic pass, install/update dependencies, typecheck/build, then migrate high-risk resource/effect/store clusters in batches with tests/diagnostics after each batch.

ResolvedFailure and done criteria.

Rollback only the failed AI semantic batch, never user work or previous successful batches. A package is called migrated only if install, typecheck/build, tests, removed-API scan, and diagnostics/report status pass.

ResolvedReports and lockfiles.

Generate machine-readable JSON plus human output. For this repo, human reports should be HTML under .reports. Best-effort mode may run the detected package manager to update lockfiles after dependency policy is settled.

API Migration Policies

Safe or Mostly Deterministic

  • batch becomes flush, including aliases, when bound to Solid.
  • Import subpaths move to @solidjs/web, @solidjs/h, @solidjs/html, and @solidjs/universal according to target profile.
  • unwrap becomes snapshot.
  • equalFn becomes isEqual; getListener becomes getObserver.
  • mergeProps becomes merge, with best-effort audit for changed undefined override semantics.
  • classList becomes class object/array forms.
  • Static parseable class:, style:, attr:, bool:, and standard on: namespace attributes should be rewritten deterministically.
  • Parseable use: directives rewrite to ref directive factories; parser failures fall back to AI/text-assisted migration.
  • ErrorBoundary becomes Errored, with binding-aware fallback error reads converted to accessor calls.
  • Suspense becomes Loading; adding Loading on is AI/evidence-based.
  • SuspenseList becomes Reveal only for documented equivalent props; unsupported/dynamic props become semantic sites.
  • Index becomes For keyed={false}; existing keyed on Index is a conflict to flag.
  • Direct createEffect(on(...)) should split deterministically when the shape is direct and bound to Solid.
  • Direct createDynamic(source, props) should deterministically become createComponent(dynamic(source), props); best-effort AI may refactor to factory + JSX.
  • Direct indexArray calls should become mapArray with non-keyed semantics when direct and bound to Solid.
  • Rest-only splitProps cases can become omit; selected-prop usages require AI.
  • Path-style store setters should first migrate to storePath(...); best-effort AI may refactor simple cases to draft-first setters.

Hybrid or AI-Gated

  • createMemo initial value migration is deterministic only for unambiguous prev default cases; ambiguous object second arguments require AI/reporting.
  • Plain 1.x createEffect calls are migration sites unless already in Solid 2 split form.
  • onMount is conditionally safe. Callbacks with cleanup or nested primitives need lifecycle-aware migration.
  • Prop destructuring and top-level reactive reads use hybrid deterministic safe cases plus best-effort diagnostics.
  • createResource is a cluster migration covering creation, value reads, loading/error, refetch, mutate, and UI boundaries.
  • Resource replacement target is shape-based: async memo for scalar/read-only values, store/projection for collection identity/granularity, optimistic/action primitives for clear mutations.
  • createComputed gets narrow deterministic rewrites for clear derived-signal and side-effect patterns; ambiguous write-back stays semantic.
  • Transitions use intent-gated AI: loading-state-only to isPending/Loading, clear mutations to action and optimistic APIs, unclear scheduling report-only.
  • from/observable are aggressively AI-migrated internally, but exported contracts must be preserved with adapters/shims unless public API breaking is enabled.
  • Nested createRoot detachment should be evidence-only; do not wrap all nested roots with runWithOwner(null, ...).

Review-Only by Default

  • createMutable and modifyMutable.
  • createDeferred.
  • enableScheduling and writeSignal.
  • Imperative error APIs such as onError, catchError, and resetErrorBoundaries unless AI has enough local context to migrate the error handling cluster.
  • /*@once*/ is intent-based. Do not blindly replace with untrack.

Library/Public API Rules

  • Preserve exported API shapes by default.
  • Private redundant context hooks may be removed; exported context hooks should be preserved or simplified internally.
  • Public API breaking mode must be explicit.

High-Priority Mismatches

Highbatch still expected as review-only.

Current fixtures expect batch to remain and be listed in review markers, conflicting with the resolved safe rename to flush. Examples: tests/source/local-safe/expected.tsx:1-2, tests/source/local-safe/expected.tsx:24, tests/source/namespace-review/expected.tsx:1, and tests/source/namespace-review/expected.tsx:7.

HighJSON dependency tests still encode same-group web insertion.

tests/json/package-all-groups/expected.json adds @solidjs/web to peer and optional groups. This conflicts with target-profile and role-aware dependency migration.

HighSome resolved deterministic rewrites remain review-only.

Fixtures still mark direct createEffect(on(...)), direct createDynamic(source, props), common createSelector, direct indexArray, and narrow createComputed as review-only. Examples: tests/source/review-only/expected.tsx, tests/source/effect-memo-dynamic-review/expected.tsx, and tests/source/review-only-remaining/expected.tsx.

HighonMount cleanup fixtures expect Solid 2-invalid output.

tests/source/onmount-cleanup/expected.tsx and tests/source/onmount-cleanup-alias-namespace/expected.tsx rename to onSettled while leaving onCleanup inside. Solid 2 diagnostics forbid this shape.

HighComplex ErrorBoundary fallback tests do not reflect binding-aware error read conversion.

tests/source/error-boundary-fallback-review/expected.tsx leaves error={err}, err.stack, and String(err). We resolved value reads of the fallback error parameter should become accessor reads where syntax permits.

Potential ADR

An ADR is likely warranted for the decision to keep deterministic codemod behavior as the default while adding explicit best-effort AI orchestration. It meets the ADR criteria discussed in the repo instructions:

  • Hard to reverse: The package architecture and user trust contract depend on this split.
  • Surprising without context: Future maintainers may ask why AI is not the default for an “absolute best effort” migration.
  • Real tradeoff: Deterministic safety and registry trust versus migration completeness and user convenience.
