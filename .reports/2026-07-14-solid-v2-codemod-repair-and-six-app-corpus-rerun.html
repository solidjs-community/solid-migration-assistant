The codemod now fails honestly and reaches a stable fixed point.

A repair agent addressed every deterministic transform defect discovered in the earlier Kanban, router, primitives, open-source, and OpenCode trials. Three independent corpus agents then reran six pinned Solid 1 applications from a frozen codemod snapshot. The result is mechanically reliable but semantically incomplete: all six migrations are exactly idempotent, all six correctly exit nonzero, and zero of six are ready to ship as Solid 2 applications.

Core outcome. The codemod no longer creates malformed effects, defers known store rewrites to a second pass, churns CRLF files, overlooks Bun catalog ownership, or reports validator failure as success through its supported runner. Remaining work is explicit in machine-readable migration manifests rather than hidden behind a successful process exit.

Correction to the earlier OpenCode report. The slash-popover class value contains escaped \n characters, not a physical newline inside a quoted string. TypeScript reports zero TSX parse diagnostics. The original “invalid multiline class” claim was a display-interpretation false positive; the exact original source is now a fixture so this cannot regress unnoticed.

Recommended next workflow

  1. Keep deterministic AST transforms narrow and proved. Add recipes only when the migration intent is inferable from syntax, bindings, types, and local data flow; require an exact reduced fixture and a corpus example.
  2. Prioritize the highest-volume semantic families. Removed exports, effects, and lifecycle APIs account for 1,243 of 1,449 blockers. Split these into sub-recipes by actual Solid 2 replacement pattern rather than one broad textual rule.
  3. Use AI only on manifested work items. Give an agent the original source, AST/binding facts, Solid 2 API contract, nearby tests, and one blocker at a time. Require a patch plus rationale, then rerun parser, typecheck, tests, validator, and exact fixed-point gates.
  4. Treat dependency migration as a separate lane. Resolve peer ranges and forbidden deep imports after workspace discovery but before claiming application completeness. Installation failure is a hard gate, not a warning.
  5. Promote corpus results into release criteria. A codemod release should require all fixtures, exact pass two, nonzero exit for unresolved work, and no regression in the subset of corpus applications whose Solid 1 baselines build.
