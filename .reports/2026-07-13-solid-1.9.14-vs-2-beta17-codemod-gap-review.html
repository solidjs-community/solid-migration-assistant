Solid 1.9.14 → 2.0 beta.17
Codemod Gap Review

Three parallel reviews compared the exact local upstream trees, then challenged solid-v2-first-pass from public-API, runtime-semantics, and codemod-engineering perspectives.

Verdict: the current workflow is a useful, behavior-verified Kanban profile, but it is not safe to run as a general Solid 1→2 migration. Several automatic rules can corrupt valid code, and many removed APIs pass through until compilation or runtime failure.

Release-blocking findings

P0 Unresolved effects are still executable

The codemod adds S2-EFFECT-001 but preserves the unsupported call. Beta.17 throws MISSING_EFFECT_FN; a comment is not a safe migrated result. Old two-argument createEffect and createMemo calls are even more dangerous because the second argument changes meaning and is not marked.

source.ts:188–203, 286–290 · beta.17 signals.ts:343–456

P0 Removed API imports pass through after the package upgrade

createResource, createSelector, createComputed, on, transitions, async boundaries, context-provider shapes, and numerous renderer helpers have no automatic rewrite or blocking inventory. The workflow can upgrade dependencies and emit code that cannot typecheck.

Solid 2 removal list: lines 133–164

P0 Store import classification can emit entirely invalid imports

Everything except four named helpers is assumed movable from solid-js/store to solid-js. Still-used removed helpers are deliberately left under a subpath that beta.17 does not export. Aliases can cause live imports to be deleted.

import { produce as mutate } from "solid-js/store";
setBoard(mutate(draft => { draft.done = true; }));
// Current result: the import is dropped because usage detection searches produce(.

source.ts:26–31, 73–85, 119–127 · beta.17 package exports

P0 Identifier names substitute for binding proof

Local functions named setBoard, createEffect, batch, onMount, Index, or persistCards can be rewritten even when unrelated to Solid. Conversely, aliases and ordinary store names such as setState are missed.

const setBoard = (...args: unknown[]) => log(args);
setBoard("theme", "dark");
// Current rule can introduce storePath into unrelated application code.

P0 classList rewrite corrupts the canonical composition case

A global text replacement turns classList={{...}} into class={{...}}. With an existing static class, the result contains duplicate class attributes. The expanded fixture currently blesses this invalid shape.

<div class="card" classList={{ active: enabled() }} />
// Required beta.17 shape:
<div class={["card", { active: enabled() }]} />

source.ts:310 · MIGRATION.md:618–625

P0 Index conversion can create mismatched JSX

The opener only matches a narrow each-only form, while every closing </Index> is replaced globally. A valid fallback, spread, or nested expression can leave <Index>...</For>.

source.ts:301–307 · Solid 1 fallback tests

P0 Package profile decisions do not constrain source or tsconfig changes

The package gate is evaluated per package.json, but every source file and every tsconfig in the target is transformed independently. In a web+library monorepo, a library can remain on Solid 1 while its imports and JSX source are changed to Solid 2 packages that were never installed.

config.ts:21–30, 73–79 · workflow.yaml:10–38

P0 Function-valued signals silently change meaning

Solid 1 stores a function first argument as a value. Beta.17 treats it as a computation. The codemod has no detector, so handler signals can become derived signals without a type error.

// Solid 1 value signal
createSignal<() => string>(() => "clicked");
// Solid 2 value signal needs an extra thunk
createSignal<() => string>(() => () => "clicked");

Important semantic holes

P1

Deferred observations

Only one literal setBoard adjacency is recognized. Signals, other stores, DOM measurement, navigation, downloads, and indirect serialization remain vulnerable to stale reads.

P1

Hidden effect dependencies

deep(board.cards) tracks the store, but any signal/store read inside persistCards becomes untracked in the apply phase. Helper call graphs need proof or inlining.

P1

Lifecycle legality and timing

The text rule proves one cleanup shape, not ownership, absence of nested primitives, or equivalence between mount completion and graph settlement.

P1

Context and root ownership

Default-less context changes from optional to throwing; createRoot's detached-owner argument changes shape. Neither is classified.

P1

JSX type coverage

import type, JSX, JSXElement, JSX runtime subpaths, re-exports, and public library surfaces are not handled.

P1

No diagnostic gate

Playwright can pass while beta.17 emits ownership, strict-read, missing-owner, or forbidden-scope diagnostics. Migration acceptance needs dev diagnostic capture.

What is actually proven today

Proven The exact Kanban profile migrates to beta.17, typechecks, builds, passes 11 unchanged browser behaviors in development and production, and is idempotent.

Not proven Binding safety, arbitrary identifiers, removed-API completeness, workspaces, libraries, custom renderers, SSR/hydration, JSONC, aliasing, import declaration variants, diagnostics, or connected async clusters.

The package should be named and presented as a Kanban/Vite CSR proving profile until the blocking analysis gates exist.

Recommended next sequence

  1. Disable unsafe automatic rules. Remove automatic mixed-class classList conversion and regex-paired Index conversion until AST-paired fixtures pass.
  2. Add a pre-mutation blocking inventory. Detect every removed import and incompatible effect/memo signature before changing package versions. A TODO cannot count as executable success.
  3. Create a beta.17 compatibility manifest. Classify every Solid 1 core, store, renderer, compiler, and type export as move, rename, deterministic rewrite, semantic cluster, or unsupported/manual.
  4. Make package profiling a shared artifact. Source, tsconfig, package, renderer, and compiler decisions must consume the same workspace/package closure.
  5. Replace text identity with binding-aware AST rules. Prove import provenance, local aliases, store tuple bindings, JSX component identity, and introduced-name collisions.
  6. Add behavior and diagnostic verification. Capture beta.17 diagnostics, same-turn observation contracts, lifecycle timing, SSR/hydration, and public declaration compatibility.
