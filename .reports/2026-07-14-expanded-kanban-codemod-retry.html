Warning and timing analysis

Closed

The intermediate reactive warning became a tested postcondition

The final probe records every console warning/error, page error, and HTTP response ≥400 while exercising the app. It observed none. The chip label changed from 1. Plan migration × to 1. Plan final ×, while the renamed card retained selected and compact classes.

This matters because the intermediate tests mostly passed despite the stale chip. Warning cleanliness plus a targeted state transition caught what assertion count alone missed.
Timing caveat

The “loading text must be visible” assertion is inherently contention-sensitive

The test tries to observe a fallback backed by a 120 ms timer. Under 20 repetitions and ten workers, the final migration passes 16/20; the separately measured Solid 1 baseline passes 17/20. Under ordinary execution, both final dev runs and preview pass the complete 16-test suite.

Verdict: retain the ordinary behavior gate, but do not use fallback visibility under artificial CPU contention as a deterministic semantic oracle. The final rate is close to baseline and materially better than the intermediate retry’s 13/20.

Validation behavior

Validator itself: correct

A clean disposable probe contains the exact unsupported one-argument effect marker and call. Running scripts/validate.ts directly through codemod jssg run exits 1 and reports S2-VALIDATE-002.

Outer workflow propagation: known CLI limitation

Codemod CLI 1.12.7 can log a validate-node runtime error yet return workflow exit 0. This was reproduced in the intermediate retry. The direct negative probe proves the local validator; it does not erase the outer CLI limitation.

Operationally, consumers should inspect structured node results or invoke the validator directly until the workflow engine reliably propagates node failures to its process status.

Residual scan

The migrated application contains none of the covered residual forms: solid-js/store, solid-js/web, removed resource/transition/boundary/selector/prop-helper imports, batch, produce, unwrap, <Index>, DOM classList=, Context.Provider, custom use: directives, or Solid 2 blocker markers.

Remaining boundaries

  1. Shape-driven support. This is still a fixture-evidenced first pass. New aliases, unusual control flow, indirect effects, or different prop/list composition need fixtures or a blocking finding.
  2. Platform scope. The workflow targets npm-based Vite client apps. SSR, alternative renderers, non-Vite builds, and other package managers remain outside the demonstrated closure.
  3. Async redesign is contextual. This resource shape migrates successfully, but arbitrary resource state APIs, mutation/refetch behavior, nested transition semantics, and streaming boundaries require separate patterns.
  4. Formatting polish. Generated code has a few awkward blank lines and indentation choices. They are not functional failures, but a formatter step would improve review quality.
  5. CLI exit propagation. A failing workflow node may not produce a nonzero outer exit with CLI 1.12.7; direct validation or structured-result enforcement remains necessary.
