Executive Summary

Kobalte has substantial Solid 2 migration work in place, but the current checkout is not buildable or testable end-to-end. The library source has many Solid 2 imports and package peer ranges, yet the build pipeline still emits solid-js/web, docs remain partly on Solid 1-era tooling, and local Solid Primitives links point at a missing sibling repo.

Best read: the branch is a meaningful in-progress migration, not a release candidate.

  • Package peers target Solid 2 beta.@kobalte/core and @kobalte/utils peer deps require solid-js and @solidjs/web ^2.0.0-beta.14.

  • Project guidance exists.MIGRATION.md documents import-path, lowercase attribute, helper rename, effect, context, store, and signal-write changes.

Main Blockers

  • Broken Solid Primitives links.Installed links point to ../../../../../solid-primitives/packages/*, but this workspace only has .repos/kobalte, .repos/solid, and .repos/test.
  • Build output imports removed path.@kobalte/core JS output still imports solid-js/web in 58 generated files.
  • Docs are not on the Solid 2 stack.apps/docs/package.json still pins solid-js 1.8.15, @solidjs/start 0.6.1, @solidjs/router 0.12.4, and @solidjs/meta 0.29.3.
  • Legacy APIs remain in source.Scans still find imports for splitProps, mergeProps, createComputed, onMount, onCleanup, on, and Index.
  • Native JSX props are partially unmigrated.Production code still uses Solid 1 style props such as autoComplete, autoCorrect, spellCheck, readOnly, contentEditable, inputMode, and tabIndex.
  • packages/dates is orphaned.It has source files but no package manifest, is outside workspaces, and calendar/date-picker exports are commented out from core.
